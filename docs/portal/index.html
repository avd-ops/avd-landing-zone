    Choose a region ·

    Ranks Azure regions by round-trip time from this browser. Run it from where your users work, not from Cloud Shell or a VPN. Under 100 ms is good for AVD, 100–150 ms is usable, above 150 ms feels sluggish.

    About 20 seconds: each region gets a warm-up request and 5 timed ones.

    Size the host pool ·

    Starts from the minimum viable kit: one memory-optimized E4as_v5 host and a 100 GiB profile share. Choose the number of hosts, or Automatic to size them from how many people use them and how they work (Microsoft's multi-session guidance: light 6, medium 4, heavy 2, power 1 user per vCPU). It suggests memory-optimized E-series sizes, because hosts shared by many users run out of memory before CPU, and every host gets a Premium SSD OS disk. Once you apply a sizing, the commands carry it: the pre-deployment preflight checks quota and availability for it, and deploy.sh deploys it. The next step prices it.

    One pooled host pool for now; the sizing is kept per host pool so more can be added later.

      Cost ·

      Most of the cost is the hours the session hosts run, and two settings decide those hours. They are deployed with the landing zone. The pre-deployment preflight prices the plan at Azure list prices for your region; after that, changing a setting here reprices it without running anything.

      Report a problem

      Opens an issue on GitHub with the output you pasted and what the portal made of it. The report is redacted here, in your browser: email addresses and UPNs, IDs, subscription, tenant, storage and key vault names, public IP addresses, your name prefix and group names, and anything that looks like a password, key or token. Nothing is sent until you submit the issue on GitHub (you need a GitHub account), and issues are public, so read the report first.
